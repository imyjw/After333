# After333 전투 모드와 골드 던전

최신 사용자 확정: 2026-10-09(골드 던전 런당 3회). 기존 모드 확정: 2026-09-13. 이 문서는 기존 PVE/PVP 버튼의 모드 구분을 대체한다. 과거 배포 기록과 현재 소스 동작을 구분한다.

## 일반 전투

- 현재 런의 33장 덱으로 사람과 우선 매칭한다.
- 임시 대기시간은 서버 기준 20초다. 상대 사람의 입장 예약이 진행 중이면 그 참가가 우선한다.
- 사람 매칭이 성립하지 않으면 같은 대기 전투를 AI 상대와 시작한다. 클라이언트가 임의로 즉시 AI 상대를 선택할 수 없다.
- 사람 또는 AI와의 일반 전투 결과는 기존 33승/3패 런 성적과 런 종료 보상에 반영한다.
- 일반 전투에서 AI를 만나도 현재 런의 골드 던전 횟수는 차감되지 않는다.
- 서버 설정 PROJECT333_MATCHMAKING_AI_WAIT_SECONDS로 대기시간을 변경할 수 있다. 현재 기본값 20초이며, 향후 30~40초로 늘리는 것은 후속 조정 사항이다.

## 골드 던전

- 플레이어는 게임 티켓 3개로 시작한 현재 진행 중인 런의 완성된 33장 덱을 사용한다. 드래프트 중이거나 끝난 런으로는 새 도전을 시작할 수 없다. 일반 런 성적과 도전 결과는 별개다.
- 상대는 [기존 10개 고정 AI 덱](pve_ai_decks.md)을 Lv.0으로 사용한다. 공격 대상 평가·생산물 보호·환술·트랩 등 현재 판단 개선은 [AI 판단 문서](pve_ai.md)에 반영되어 있다. 별도 난도 선택과 도전 전용 덱 편성은 추가하지 않았다.
- 티켓 3개로 시작한 런마다 최대 3회 도전할 수 있다. 자정·날짜 변경·앱 재실행·재로그인은 횟수를 초기화하지 않는다. 새 티켓 3개를 지불해 새 런을 시작하면 그 런에 별도의 3회가 주어진다.
- 도전 버튼의 시작 요청을 서버가 수락할 때 1회 차감한다. 중복 클릭과 같은 요청 재시도는 같은 도전으로 처리하여 중복 차감하지 않는다.
- 승리 보상은 서버 골드(Resource Gold) 10, 패배 보상은 0이다. 무승부도 승리가 아니므로 승리 보상을 지급하지 않는다.
- 서버가 확정한 결과만 보상을 지급하며, 결과 기록과 골드·거래 기록은 하나의 트랜잭션으로 처리한다. 재전달로 두 번 지급하지 않는다.
- 도전의 승패는 일반 런의 승수·패수, 런 종료 조건, 런 종료 보상을 변경하지 않는다.
- 던전 입장마다 별도의 티켓을 내지는 않는다. 런을 시작할 때 지불한 티켓 3개에 그 런의 던전 최대 3회가 포함된다. 사용하지 않은 횟수는 런 종료 후 다른 런으로 이월하지 않는다.
- 도전 시작 응답 후 앱이 닫혀도 서버에 남은 동일한 도전으로 입장하며 새 횟수를 차감하지 않는다.

### 런별 횟수와 표시

- 서버는 인증 계정과 현재 `RunId`에 속한 비환급 도전 수를 날짜와 무관하게 합산한다. 남은 횟수는 `max(0, 3 - 사용 횟수)`다. 변경 전 현재 런에서 이미 사용한 도전도 포함하며, 3회 이상 사용했다면 잔여 0회로 표시한다. 기존 기록·확정 결과·보상은 변경하지 않는다.
- `/ai-challenge/status`는 `RunId`, `RunLimit`(3), `RemainingAttempts`, `PendingAttempt`를 반환한다. 일일 초기화 시각은 반환하지 않는다. 입장 가능한 완성된 진행 중 런이 없으면 새 도전은 불가능하며 잔여 횟수는 0이다.
- 버튼의 `골드 던전 (1/3)`은 **현재 런에서 남은 횟수 1회**를 뜻한다. 클라이언트는 인증된 서버 응답을 표시하고 날짜나 로컬 저장값으로 횟수를 보충하지 않는다.
- 기존 `challenge_day`는 저장된 날짜 감사 정보로 유지하되 입장 한도·환급의 기준으로 사용하지 않는다. 신규 `0023_ai_challenge_run_usage.sql`은 계정·런별 비환급 도전 조회 인덱스만 추가한다. 기존 행 삭제·초기화·보상 재정산은 없다.

## 재접속과 서버 취소

- 시작 화면과 덱 화면에서 '전투 재접속 (남은 시간)'으로 원래 전투를 이어간다.
- 서버는 전투 목적(run / ai_challenge)과 상대 종류(사람 / AI)를 구분한다. 사용자가 재접속 경로를 고를 필요가 없다.
- 연결 끊김을 감지한 뒤 70초 동안 기존 전투·좌석·덱·강화·전장으로 재접속한다. 기존 턴 시간과 AI 진행은 유지한다.
- 앱 종료 및 70초 재접속 만료에 의한 도전 패배는 횟수를 복구하지 않는다.
- 서버 장애·점검으로 미완료 전투가 취소되면 승패·보상을 기록하지 않는다. 취소된 골드 던전은 해당 도전이 속한 원래 `RunId`의 횟수만 복구한다. 이전 런의 취소가 현재 새 런에 추가 횟수를 만들지 않는다.
- 서버 재시작 시 이미 확정되어 영속 결과 저널에 남은 결과를 먼저 처리하고, 나머지 미완료 도전만 취소·횟수 복구한다.

## API

- GET /ai-challenge/status: 현재 런 ID, 런 한도 3회, 런 잔여 횟수, 진행 대기 도전.
- POST /ai-challenge/start: RequestId, RunId, DeckId를 보내 도전 시작을 요청.
- GET /ai-challenge/attempts/{id}: 자기 도전의 확정 결과·지급 골드 조회.
- GET /battle/reconnect-status: 기존 전투 ID·남은 시간·상대 종류·전투 목적·도전 ID 조회.
- 기존 /pvp/reconnect-status는 구형 앱 호환을 위해 사람 전투만 반환한다.

## 구현·검증·배포 기록 (2026-09-13)

아래는 당시 일일 3회 규칙의 검증·배포 기록이다. 현재 런당 3회 규칙의 검증이나 운영 반영으로 해석하지 않는다.

- 서버 통합 검사 114개와 실제 격리 서버 종료·재시작 검사가 통과했다. 20초 후 같은 대기방에서 AI 전투 시작, 사람 입장 예약 우선, 일반 런 성적 반영, 일일 제한·한국시간 자정 경계·중복 보상 방지·서버 취소 시 원래 날짜의 횟수 복구를 포함한다.
- AI로 전환된 대기방의 이전 참가자는 새 도전을 시작할 수 있으며, 실제 AI 전투 참가자는 연결 중과 60초 재접속 대기 중 모두 새 도전을 시작할 수 없다.
- 최초 도전 접속은 실제 전투 상태가 생긴 뒤에만 진행 중으로 기록한다. 시작 전 연결이 끊기면 같은 예약을 재사용하고, 시작 후 끊기면 기존 60초 재접속을 적용한다.
- Unity EditMode 검사 1,204개가 통과했다. 복제한 Unity 프로젝트에서 실제 시작·덱 씬을 렌더링해 공통 재접속 버튼, 예약 도전 이어하기, 전투·골드 던전 잔여 횟수 표시를 확인했다. 휴대폰 앱을 새로 빌드하거나 설치한 검증은 아니다.
- 운영 서버는 2026-09-13 19:10 KST에 `20260913-battle-modes-verified` 릴리스로 교체했다. 진행 중인 전투 0개를 확인하고 배포 직전 DB 백업을 생성했으며, 복원은 하지 않았다.
- DB 마이그레이션 0018·0019 적용, 기존 계정·런 성적·지갑·컬렉션·거래·요청 결과 기록의 동일성을 확인했다. 로컬·공개 주소의 상태, 새 API 인증 차단, 공개 WSS 연결도 통과했다.

## 골드 던전 버튼 연결 수정 (2026-09-25)

아래의 하루 도전 횟수 유지 설명은 당시 규칙이다. 현재 입장 한도는 위의 런별 규칙을 따른다.

- 골드 던전은 일반 매칭 대기열을 거치지 않고 서버 도전 예약을 받아 AI 전투에 바로 입장한다.
- 드래프트·덱 씬의 기존 StartBattleButton은 골드 던전 버튼으로 재사용된다. 저장된 StartBattleFromUi 연결도 골드 던전으로 해석한다.
- 버튼을 구성할 때 이 컨트롤러의 예전 전투 시작 이벤트만 해제하고 해당 모드의 실행 이벤트를 한 번 연결한다. 일반 전투 버튼은 기존 일반 매칭을 사용한다.
- 씬 생성기도 골드 던전 버튼에 StartPveBattleFromUi를 연결한다. 하루 도전 횟수·차감·보상·재접속 규칙은 그대로다.

## 2026-09-28 재접속 시간 변경

일반 사람/AI 전투와 골드 던전의 연결 끊김 유예를 60초에서 70초로 변경했다. 서버가 감지한 시점부터 계산하며 재접속 버튼의 남은 시간은 서버 기한을 따른다. 턴 제한·AI 진행·만료 패배·서버 장애 취소 규칙은 유지한다. 위 과거 배포 기록의 60초는 당시 값이다. 최신 변경의 운영 적용에는 서버 업데이트와 클라이언트 빌드가 필요하다.

## 2026-10-01 공개 명칭 변경

아래의 일일 초기화 유지 설명은 당시 명칭 변경의 범위다. 2026-10-09부터 적용할 소스 규칙은 위의 런당 3회다.

- 기존 일일 AI 대전 모드의 공개 명칭을 **골드 던전**(영문: Gold Dungeon)으로 변경했다. 화면의 버튼·안내와 현재 규칙·가이드 문서에 같은 명칭을 사용한다.
- 명칭만 변경한다. KST 자정 초기화·하루 3회·승리 Resource Gold 10·패배 0·일반 런 성적과 분리·기존 차감/재접속/서버 취소 환급 규칙은 유지한다.
- `ai_challenge`, `/ai-challenge/*`, 관련 클래스·메서드·DB·저장 키는 호환성을 위해 그대로 유지한다. 과거 검증 자료의 파일명·식별자·배포 기록을 새 이름으로 바꾸지 않는다.
- 위 과거 기록의 모드 명칭도 현재 이름으로 갱신했다. 당시 화면에 새 이름이 표시됐다는 뜻이나 당시 검증을 다시 수행했다는 뜻은 아니다.
- 이번 명칭 변경으로 앱 빌드·설치나 서버 배포·재시작을 수행하지 않았다.

## 2026-10-09 런당 3회 변경

- 하루 3회·KST 자정 초기화를 티켓 3개로 시작한 런당 최대 3회로 변경한다. 기존 진행 중인 런도 그 런의 누적 도전을 기준으로 계산한다.
- 보상, 정상 종료·재접속·중복 요청 처리와 일반 런 성적 분리 규칙은 유지한다. 서버 취소 환급은 차감한 원래 런에만 반영한다.
- 이번 소스 변경으로 운영 서버 배포·재시작, 운영 DB 마이그레이션 적용 또는 클라이언트 빌드·설치를 수행한 것으로 해석하지 않는다.

## 운영 DB 마이그레이션 적용 (2026-10-09)

사용자 요청으로 12:57 KST 운영 `project333` DB에 `0023_ai_challenge_run_usage`를 적용했다. 현재 총 23개/latest 0023이며 부분 인덱스 `ai_challenge_run_usage_idx(account_id, run_id) WHERE refunded_at IS NULL`의 valid/ready 상태를 확인했다. 적용 직전 보호된 로컬 경로에 전체 백업을 저장하고 아카이브 전체 읽기를 검증했다. 마이그레이션 이력을 제외한 기존 33개 테이블의 행 수와 전체 행 해시가 적용 전후 일치했고, 도전 기록 25건을 그대로 유지했다. 이번 작업은 DB 적용만 완료했으며 런당 3회 규칙의 서버 배포와 클라이언트 빌드·설치는 아직 별도 작업이다.
