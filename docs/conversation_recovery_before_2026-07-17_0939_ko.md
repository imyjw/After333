## 3. 시간순 작업 이력 복원

### 3.1 초기 전투 보드와 공격 연출

초기에는 5×2 타일 보드 위에서 유닛을 소환하고 이동하고 공격하는 로컬 전투를 먼저 만들었다.

주요 조정 내역은 다음과 같다.

- 근접 공격자가 상대 타일 이미지 중심과 겹치지 않도록 접촉 위치를 조정했다.
- 최종적으로 상대가 AI이면 대상 기준 (-30, +30), 상대가 Player이면 (+30, +30)을 사용하도록 조정했다.
- TileTextView의 기본 소환물 시각 오프셋을 Y +60으로 올렸다.
- 소환물 위치를 20px 올린 뒤 공격 기준점도 함께 올려 공격 시 아래쪽을 치는 것처럼 보이지 않게 했다.
- 케르베로스만 Y -16을 적용하던 예외를 제거하고 다른 카드와 같은 소환 기준을 사용하게 했다.
- 근접 반격에서도 Attack 애니메이션이 실행되게 했다.
- Attack과 BeAttacked가 동시에 덮어쓰이지 않도록 Attack 후 BeAttacked 순서로 재생되게 했다.
- 파이어볼 같은 마법 피해에도 BeAttacked 애니메이션이 재생되게 했다.
- 반격 템포와 attackImpactDelay를 줄여 전투가 지나치게 느리지 않게 했다.
- 피해량은 빨간색, 회복량은 초록색 숫자로 약 1초 표시하게 했다.
- 케르베로스 같은 다단히트는 타격마다 숫자가 따로 표시되게 했다.
- 다단히트 숫자 간격은 stackIndex × 16, 표시 간 지연은 0.18초로 조정했다.
- 선택한 타일은 옅은 붉은색으로 표시되게 했다.

### 3.2 게임 시작 씬 제작

게임 실행 시 가장 먼저 나오는 GameStart 씬을 새로 만들었다.

주요 흐름은 다음과 같다.

- 화면 중앙의 시작 버튼을 누르면 게임 티켓 3개를 차감한다.
- 티켓 차감에 성공하면 Draft_VSlice.unity로 이동한다.
- 사용자가 제공한 게임 시작 배경 이미지를 연결했다.
- 사용자가 제공한 START 버튼 이미지를 게임 시작 버튼에 연결했다.
- 이후 프로젝트 명칭을 Project333에서 After333으로 변경했다.
- 로컬 데모 티켓 표시는 나중에 제거했다.
- 서버 티켓과 골드는 서버 계정 정보로 표시하도록 전환했다.
- 골드 3개로 티켓 1개를 구매하는 버튼을 추가했다.

### 3.3 손패 시스템과 하스스톤식 입력

손패 최대치는 처음 9장에서 13장으로 늘렸고, 이후 기본 최대치를 10장으로 낮췄다.

현재 확정된 규칙은 다음과 같다.

- 기본 최대 손패는 10장이다.
- 효과로 최대 손패를 늘릴 수 있지만 절대 13장을 넘을 수 없다.
- Card Grader는 소환 시 최대 손패 +1 카드로 기획했지만 실제 완성은 뒤로 미뤘다.

손패 UI와 입력은 다음과 같이 발전했다.

- 런타임에만 생기던 10~13번째 슬롯을 기존 Hand_00~08과 같은 편집 가능한 구조로 정리했다.
- 카드를 선택하면 기울어진 각도를 유지하지 않고 정면으로 펴진 상태에서 1.75배 확대되게 했다.
- 드래그 중에는 화면을 가리지 않도록 0.4배 크기로 축소되게 했다.
- 낼 수 있는 카드에는 초록색 테두리 glow를 표시했다.
- 카드 크기와 bottom padding을 바꿔도 카드 이미지 자체가 클릭 영역이 되게 했다.
- 클릭 후 타일을 다시 클릭하는 방식에서 손패의 카드를 타일로 드래그하는 방식으로 바꿨다.
- 타일 대상 유닛과 마법은 드래그 중 가리키는 타일을 붉게 표시했다.
- 타일 대상이 없는 마법은 손패에서 위로 드래그하면 사용되게 했다.
- 선택된 손패 카드가 유닛, 스탯바, 상대 카드 공개 연출보다 위에 보이도록 레이어를 조정했다.
- 멀리건 UI는 손패보다 위에 표시되게 했다.
- 타일과 버튼이 아닌 빈 화면을 누르면 확대된 손패 선택이 해제되게 했다.

### 3.4 마법 카드 연출

파이어볼을 시작으로 마법 카드의 시각 효과를 추가했다.

- 파이어볼 스프라이트 시트를 여러 차례 교체했다.
- 파이어볼 효과는 유닛과 건물 애니메이션보다 높은 레이어에 표시되게 했다.
- 서버 전투에서도 파이어볼 사용 시 목표 한 곳에만 효과와 피해 숫자가 한 번 표시되게 했다.
- 천라지망은 대상 유닛 위에 그물 오버레이를 표시하고 다음 자기 턴의 파괴 효과가 발동할 때까지 유지했다.
- 천라지망 오버레이 위치는 총 60px 아래로 내렸다.
- 마법 효과의 위치도 반응형 타일 크기와 소환물 위치 보정에 맞춰 조정했다.

### 3.5 애니메이션과 빌드 문제 해결

PixelFantasy 에셋의 Editor 스크립트가 Player 빌드에 섞여 UnityEditor 타입을 찾지 못하는 문제를 수정했다.

확인된 문제 유형은 다음과 같았다.

- InitializeOnLoad를 찾지 못하는 빌드 오류
- CustomEditor를 찾지 못하는 빌드 오류
- 에디터에서는 재생되지만 빌드에서 유닛 애니메이션이 작동하지 않는 문제

Editor 전용 코드를 빌드 대상에서 분리하고 런타임 애니메이션 참조가 빌드에 포함되도록 정리했다.

### 3.6 전투 UI 정리와 반응형 화면

초기 개발 UI 중 SelectedCardText, SelectedOccupantText, ResolveTurnStartButton은 제거했다.

전투 UI는 다음 방향으로 정리했다.

- TurnText는 오른쪽 상단에 배치했다.
- EndTurn 버튼은 크게 만들어 오른쪽 중앙에 배치했다.
- PassMulliganButton은 오른쪽 하단에 배치했다.
- PlayerResourcesText는 왼쪽 하단에 배치했다.
- AIResourcesText는 왼쪽 상단에 배치했다.
- CombatLogText는 왼쪽 중단에 배치했다.
- InteractionStatusText와 SummaryText는 비활성화했다.
- HandPresenter의 Bottom Padding은 0으로 설정했다.
- CastSelectedSpellButton과 RestartButton은 전투 씬에서 완전히 삭제했다.
- 개발용 즉시 승리·패배 명령도 최종적으로 제거했다.

보드 자체도 모바일과 PC에서 반응형으로 바꿨다.

- 화면 높이를 넘지 않는 선에서 타일 크기를 균일하게 확대한다.

- BoardPresenter의 Board Outward Offset은 170으로 설정했다.
- 타일 크기가 커지면 소환물 스프라이트, Animator, 스탯바, 공격 접촉점, 마법 효과 위치도 같은 비율로 보정한다.
- 단순히 크기만 키우지 않고 타일 중심과 visual lift 기준도 함께 스케일링한다.

### 3.8 전투 규칙의 확장

기본 보드는 각 플레이어가 5×2 타일을 가진다.

현재 핵심 규칙은 다음과 같다.

- 좌표는 (column, row)이다.
- row 0은 전열, row 1은 후열이다.
- 마스터는 (2,1)에서 시작한다.
- 마스터 기본 능력치는 ATK 3, HP 333이다.
- 마스터는 이동 가능한 근접 공격자다.
- 공격력이 0인 소환물은 공격과 반격을 할 수 없다.
- 근접 대 근접만 반격한다.
- 원거리 공격에는 반격하지 않는다.
- 한 공격 또는 효과의 피해 처리가 끝나면 HP 0 이하 소환물을 즉시 제거한다.

덱과 첫 턴 규칙은 다음과 같다.

- 양쪽 덱은 매 전투마다 독립적으로 셔플한다.
- 선공과 후공은 서버가 무작위로 정한다.
- 양쪽 시작 손패는 3장이다.
- 시작 자원은 마나 0, 기 0, 전력 0, 골드 3이다.
- 선공은 첫 턴에 기본 골드 +1을 받지 않아 3골드로 시작한다.
- 후공은 선공 턴 동안 3골드이고 자기 첫 턴 시작에 +1을 받아 4골드가 된다.

### 3.9 멀리건

하스스톤식 중앙 카드 멀리건 화면을 구현했다.

- 제한 시간은 33초다.
- 중앙에 시작 손패 3장을 크게 표시한다.
- 원하는 카드를 선택하고 교체 버튼을 누른다.
- 선택한 카드는 잠시 덱 밖에 둔 채 나머지 덱에서 같은 수만큼 뽑는다.
- 교체된 카드를 중앙에서 3초 보여준 뒤 멀리건 화면을 닫는다.
- 먼저 확정한 플레이어는 상대의 멀리건을 기다리는 중...을 본다.
- PVE AI는 교체하지 않고 현재 패를 유지한다.
- 양쪽 멀리건 화면이 끝난 후에만 AI가 행동한다.
- 멀리건 화면에는 자신이 선공인지 후공인지 표시한다.

### 3.10 AI 행동과 전투 템포

AI는 한 번에 모든 행동을 계산해 애니메이션을 겹치게 하지 않고, 한 소환물씩 순차적으로 행동하도록 바꿨다.

- 각 공격 직후 피해와 HP 변화를 적용한다.
- 모든 공격 애니메이션이 끝난 뒤 한꺼번에 HP가 줄어드는 문제를 수정했다.
- AI가 멈춘 채 턴을 넘기지 않는 경우를 막는 종료 보완을 넣었다.
- AI가 카드를 사용하면 실제 소환 또는 마법 처리를 먼저 반영하고 상대 카드 공개 연출을 보여준다.
- AI는 카드 한 장을 사용한 뒤 3초 기다리고 다음 행동을 한다.

### 3.11 상태이상과 특수효과 기반

#### 방전 Drained

전력 유지비를 지불하지 못한 유닛과 건물은 방전된다.

- 공격, 반격, 이동 불가
- 효과 발동 불가
- 전열 차단 불가
- 물리·마법 방어력 0
- 물리·마법·고정 피해 모두 3배
- 타일은 계속 점유
- 대상으로 지정 가능
- 전력을 다시 지불하면 정상 상태로 복귀

유지비 대상은 문명 이름이 아니라 sciencePowerUpkeep > 0인지로 판단한다.
골드는 전력 유지비도 1:1로 대신 지불할 수 있다.

#### 망각 Erasure

기존 Disabled 개념은 망각으로 재정의했다.

- 카드 효과와 버프·디버프를 무효화한다.
- 기본 ATK/HP, 계정 강화 수치, 공격 타입, 데미지 타입, 이동 여부, 타일 크기, 기본 방어력은 유지한다.
- 광전사, 연타, 추가 공격, 불굴, 가드, 흡혈, 속공, 복제 관련 특성, 자원 생산, 로봇 공장, 주문력, 은신, 비행, 무적 등을 억제한다.
- 전력 유지비도 억제하며 망각 적용 즉시 기존 방전은 해제된다.
- 로봇 분류 태그도 전투 검색에서는 무효화한다.
- 로봇 합체나 대환단으로 받은 전투 중 능력치 증가는 망각 적용 시 제거한다.
- 방어력을 0으로 만들거나 받는 피해를 3배로 만들지는 않는다.
- 평범한 전열 소환물이라면 계속 전열을 막는다.
- 봉인은 망각으로 제거되지 않는다.
- 코드와 스냅샷은 IsErasure을 사용하고 과거 IsDisabled를 복원 시 변환한다.

### 3.12 피해 유형과 방어력

피해를 물리, 마법, 고정으로 분리했다.

계산식은 다음과 같다.

- 물리 최종 피해 = max(0, 원래 피해 - 물리 방어력)
- 마법 최종 피해 = max(0, 원래 피해 - 마법 방어력)
- 고정 피해는 방어력을 무시한다.
- 다단히트는 매 타격마다 방어력을 따로 적용한다.
- 방전의 3배 피해는 고정 피해에도 적용한다.
- 덱 고갈 피해는 고정 피해다.
- 당시 존재하던 개발용 333 피해도 고정 피해로 취급했으나 개발 명령 자체는 이후 삭제했다.

Guard 처리 규칙은 다음과 같다.

- Guard 자신의 방어력을 먼저 적용한다.
- Guard의 남은 HP를 넘는 피해만 원래 보호 대상에게 전달한다.
- 전달된 피해에는 보호 대상의 방어력을 다시 적용한다.

LifeSteal은 방어 적용 후 실제 감소시킨 HP만큼 회복한다.

전투 처리 순서는 다음과 같이 확정했다.

1. 공격자 피해 적용
2. 반격자 피해 적용
3. HP 0 이하 소환물 제거
4. 살아남은 공격자의 LifeSteal 회복
5. 살아남은 반격자의 LifeSteal 회복

### 3.14 로봇 시스템

A-111에 로봇 태그를 붙였고 이후 로봇 합체와 로봇 공장을 추가했다.

#### 로봇 합체

- 내 필드의 살아 있는 로봇 유닛이 2개 이상이면 사용할 수 있다.
- CardId가 같아도 서로 다른 두 소환물이면 선택할 수 있다.
- 손패에서 위로 드래그해 비용을 지불하고 선택 모드로 들어간다.
- 선택한 타일은 선택 표시가 켜진다.
- 2개 이상 선택하면 합체 버튼이 나타난다.
- 전력 유지비가 가장 높은 로봇이 생존한다.
- 유지비가 같으면 먼저 선택한 로봇이 생존한다.
- 흡수된 로봇의 현재 ATK와 현재 HP를 생존 로봇에게 더한다.
- 특수효과, 공격 횟수, 데미지 유형, 유지비, 방전·망각 상태는 전달하지 않는다.
- 흡수된 로봇은 처치가 아니라 합체 재료 제거로 기록한다.

#### 로봇 공장

- 과학 문명 1×1 건물이다.
- Rare, 전력 1, HP 50, 공격 불가, 이동 불가다.
- 전력 유지비 1을 가진다.
- 자기 턴 시작에 덱 빌딩에 포함된 hasRobot 유닛 중 하나를 동일 확률로 생성한다.
- 공장이 여러 개면 타일 순서대로 공장마다 한 장씩 생성한다.
- 손패가 가득 차면 생성 카드는 즉시 소멸한다.
- 생성 카드는 해당 계정이 보유한 카드 강화 레벨을 사용한다.
- 상대는 카드 정체를 보지 못하고 상대가 카드 1장을 획득했다는 사실과 손패 수 증가만 본다.
- 로봇 공장 자체는 로봇이 아니다.
- 방전, 망각, 봉인 중에는 발동하지 않는다.

### 3.15 새 특수효과 구현

#### 속공 Rush

- 소환한 턴의 공격 제한만 해제한다.
- 이동 제한이나 공격 횟수를 추가로 주지는 않는다.
- A-111에 적용했다.

#### 복제 Replicate

- 카드를 사용한 뒤 원래 카드의 임시 사본을 손패에 추가한다.
- 비용이 0인 카드도 복제할 수 있다.
- 원본 카드가 전투 중 비용 감소를 받았더라도 사본은 기본 비용으로 돌아간다.
- 계정 강화 레벨은 유지한다.
- 전투 중 원본에 붙은 임시 비용, ATK 등의 변경은 복사하지 않는다.
- 임시 사본은 턴 종료 시 사라진다.

#### 봉인 Sealbound

- card data의 sealboundOwnerTurnStarts가 1 이상이면 소환 직후 봉인된다.
- 소환한 턴은 세지 않고 이후 소유자 턴 시작 마지막 단계마다 1 감소한다.
- 0이 되면 봉인이 해제된다.
- 봉인 중 타일은 점유하지만 공격, 반격, 이동, 교환, 효과, 유지비 처리를 하지 않는다.
- 공격, 단일 마법, 광역 피해, 회복, 버프·디버프의 대상이 될 수 없고 피해도 받지 않는다.
- Guard, 로봇 합체, 로봇 공장 검색, 전열 차단에서 제외된다.
- 해제된 턴에는 속공이 있을 때만 바로 공격할 수 있다.
- 봉인 중에는 방전과 망각 판정을 멈춘다.
- 봉인 상태인 카드는 망각의 영향을 받지 않는다.
- 마스터에는 적용하지 않고 유닛과 건물에만 적용한다.
- 재접속 스냅샷에 봉인 여부와 남은 횟수를 저장한다.

#### 은신 Hiding

- 유닛 전용이다.
- 상대 일반 공격과 상대 단일 대상 마법의 대상이 되지 않는다.
- 전열 차단과 Guard에 참여하지 않는다.
- 합법적인 일반 공격을 선언하면 공격 전에 영구 해제된다.
- 방전 또는 망각에 들어가면 영구 해제된다.
- 방전·망각이 풀려도 다시 은신하지 않는다.
- 광역 효과와 비대상 효과에는 영향을 주지 않는다.

#### 비행 Flying

- 유닛, 건물, 마스터가 가질 수 있다.
- 원거리 공격자 또는 비행 공격자만 활성 비행 소환물을 일반 공격할 수 있다.
- 비행 근접 유닛은 상대 전열 차단을 무시하고 후열을 공격할 수 있다.
- 반격 조건 자체는 기존 근접 대 근접 규칙을 따른다.
- 활성 비행 소환물은 전열 차단을 하지 않는다.
- 비행은 공격해도 해제되지 않는다.
- 방전과 망각은 비행 효과를 억제한다.
- 레드 드래곤과 블루 드래곤에 적용했다.

#### 주문력 SpellPower

- 살아 있고 효과가 활성화된 아군 소환물의 주문력을 합산한다.
- 마법 카드가 만드는 Magic 피해에만 더한다.
- Physical, Fixed, 일반 공격, 유닛·건물 효과에는 적용하지 않는다.
- 광역은 대상마다, 다단히트는 타격마다 주문력 전체를 더한다.
- 지속 마법은 손패에서 사용한 순간의 주문력을 저장해 이후에도 그 값만 사용한다.
- 방전, 망각, 봉인 상태에서는 주문력을 제공하지 않는다.
- 은신과 비행은 주문력을 억제하지 않는다.

#### 무적 Invincible

- 물리, 마법, 고정 피해로 HP가 감소하지 않는다.
- 대상 지정 자체는 허용한다.
- 피해 외 제거 효과는 막지 않는다.
- Always, SummonTurn, OwnerTurnOnly, OpponentTurnOnly, UntilTurnEnd, OwnerTurns 지속 방식을 지원한다.
- 내 n턴 동안은 소유자의 턴 종료를 n번 맞을 때까지 유지한다.
- 방전과 망각은 무적을 억제하지만 지속 시간은 계속 흐른다.
- 재접속 스냅샷에 지속 방식과 남은 횟수를 저장한다.

### 3.16 특수효과 툴팁

전장 소환물을 길게 누르면 카드 이미지와 특수효과 설명 창을 함께 표시하도록 만들었다.

- 카드 왼쪽에 최대 3개, 오른쪽에 최대 3개를 배치한다.
- 1~2개는 왼쪽에 표시한다.
- 3~4개는 좌우에 나눈다.
- 5개는 왼쪽 3개, 오른쪽 2개다.
- 6개는 좌우 3개씩이다.
- 로봇 태그는 별도 툴팁으로 표시하지 않는다.
- 전력 유지비, 버서커, 연타, 추가 공격, 불굴, 가드, 흡혈, 속공, 복제, 방전, 망각, 봉인, 은신, 비행, 주문력, 무적을 설명 대상으로 정했다.

### 3.18 카드 데이터의 JSON 전환

초기에는 Unity ScriptableObject가 카드 데이터의 중심이었다.

- 제한 시간이 20초 이하일 때만 타이머 UI를 보여준다.
- 서버 시간이 기준이므로 두 클라이언트가 자기 로컬 카운트만 따로 재지 않게 했다.
- Application.runInBackground를 켜 포커스를 잃어도 Unity가 업데이트되게 했다.

PVP 접속 종료 규칙은 다음과 같다.

- 상대가 끊겨도 남은 플레이어는 자기 턴을 계속할 수 있다.
- 끊긴 플레이어의 턴이 와도 서버 턴 시간은 계속 흐른다.
- 상대 재접속 대기 시간은 60초다.
- 남은 클라이언트에는 상대의 재접속을 기다리는 중...nn을 표시한다.
- 60초 안에 같은 계정으로 돌아오면 같은 matchId와 seat에 재접속한다.
- 60초가 지나면 몰수패 처리한다.
- 몰수승 시 상대가 도망쳤습니다를 표시한다.
- 이미 종료된 전투의 재접속 버튼을 누르면 승리, 패배 또는 이미 종료됨 안내 모달을 표시한다.
- 확인 버튼은 모달만 닫고 씬을 강제로 이동하지 않는다.
- 모바일에서 Wi-Fi와 데이터가 바뀌는 상황을 위해 자동 재접속 루프를 추가했다.

### 3.21 전투 스냅샷과 구조화된 로그

PVP 재접속과 서버 재시작 복구를 위해 다음을 저장한다.

- 전투 도메인 상태 snapshot
- 처리된 명령 log
- 계정과 seat
- 현재 턴과 마감 시각
- 손패, 덱, 자원, 보드 소환물
- 상태이상과 특수효과의 런타임 값
- 최근 구조화된 전투 기록 33줄

CombatLog 설계는 다음처럼 분리했다.

- 게임 판정은 서버 권위다.
- 서버는 언어 중립적인 구조화 기록을 저장한다.
- Unity 클라이언트가 구조화 기록을 한국어 문장으로 바꾼다.
- CombatLogText는 최근 33줄을 스크롤 영역에 보관한다.
- 새 기록이 오면 자동으로 아래로 스크롤한다.
- 재접속 시 서버 snapshot의 최근 기록을 복원한다.

초기 연결 정보, 디버그 메시지, 멀리건 전송 메시지 같은 것은 CombatLogText에서 제거했다.

### 3.22 PostgreSQL과 계정 DB

- JSON과 일반 관계형 데이터를 함께 다루기 좋다.
- 실제 온라인 서비스 구조로 확장하기 적합하다.

### 3.23 로그인과 자동 로그인

로그인 방향은 최종적으로 다음과 같이 바뀌었다.

- 게스트 계정은 제거했다.
- 계정 전환도 일반 사용자 흐름에서 제거했다.
- 처음 실행했을 때 로그인하지 않았다면 게임 기능을 사용할 수 없다.
- 게임 ID 회원가입과 로그인을 지원한다.
- Google 로그인을 지원한다.
- 한 번 로그인하면 세션 토큰과 refresh token을 안전한 저장소에 보관한다.
- 다음 실행부터 자동 로그인한다.
- Android는 Keystore 기반 보안 저장을 사용한다.
- iOS용 Keychain 경계도 마련했다.
- 기존 PlayerPrefs 자격 증명은 보안 저장소로 migration한다.

Google 로그인은 다음 흐름까지 확인했다.

- Google Cloud Desktop, Web, Android OAuth 클라이언트 설정
- Windows 브라우저 로그인
- Android Credential Manager 기반 계정 선택
- 같은 Google 계정으로 카드, 골드, 덱 유지
- 게임 재실행 자동 로그인
- 로그아웃 후 재로그인

Kakao와 Naver identity 자리는 DB에 준비되어 있지만 실제 로그인 구현은 남아 있다.

### 3.24 드래프트, 덱 빌딩, 런 저장

기존 Draft 씬에서 3장 중 1장을 골라 33장을 만드는 부분을 DeckBuilding 씬으로 분리했다.

현재 흐름은 다음과 같다.

- GameStart에서 티켓 3개를 소비해 새 run을 시작한다.
- DeckBuilding에서 서버가 제시한 3장 중 1장을 선택한다.
- 선택할 때마다 서버와 DB에 즉시 저장한다.
- 현재 제시 중인 3장도 서버에 저장한다.
- 게임을 종료해도 선택한 카드와 현재 오퍼를 그대로 복원한다.
- 33장을 모두 선택하면 서버가 덱을 완성한다.
- Draft 씬은 완성된 덱, PVE/PVP 진입, 승패, 보상 흐름을 담당한다.
- DeckBuilding의 뒤로가기는 진행 상황을 버리지 않고 GameStart로 돌아간다.
- 다시 시작하면 계속하기 흐름으로 들어간다.

덱 빌딩 UI는 다음과 같이 정리했다.

- 세 카드 영역을 화면 크기에 맞게 자동 조절한다.
- DeckPanel은 오른쪽에 배치한다.
- OptionTitle과 OptionSubtitle은 제거했다.
- ProgressText는 제거하고 StatusText만 유지했다.
- StatusText 원래 문구는 유지했다.
- TitleText와 StatusText는 화면 위에 배치했다.
- 카드 영역 간격은 최종적으로 50으로 조정했다.
- 덱 목록은 길어지면 스크롤할 수 있게 했다.
- 제시 카드에 실제 강화 ATK/HP와 레벨을 표시한다.

### 3.25 런 승패와 보상

한 드래프트 덱은 33승 또는 3패까지 사용한다.

- 전투마다 해당 계정의 현재 카드 강화 레벨을 적용한다.
- PVE와 PVP는 같은 run/deck 저장 구조를 사용한다.
- run이 끝나면 보상을 한 번만 받을 수 있다.
- 보상 수령 후 새 run을 시작할 수 있다.
- 임시 골드 보상은 승리 수 × 3이다.
- 카드 보상 수량도 승리 수 × 3으로 정했다.
- 보상 가능 카드만 후보에 들어간다.
- 강화 불가능 카드와 includeInRewards false 카드는 제외한다.

임시 희귀도 확률은 다음과 같다.

- Common 40%
- Uncommon 30%
- Rare 18%
- Unique 9%
- Legendary 3%

보상 결과창은 높은 희귀도부터 표시한다.

1. Legendary
2. Unique
3. Rare
4. Uncommon
5. Common

보상 결과창을 확인한 뒤 화면을 누르면 GameStart로 복귀하게 했다.

### 3.26 보유 카드와 강화

OwnedCards 씬을 만들고 GameStart에 보유 카드 버튼을 추가했다.

목록 UI는 다음과 같다.

- 한 페이지에 6×2, 총 12장 표시
- 왼쪽과 오른쪽 화살표로 페이지 이동
- 카드 이미지 아래에 현재 레벨과 보유 카드/필요 카드 수 표시
- 강화 가능하면 슬롯 테두리를 초록색으로 표시
- 상세 패널에서 비용, 소속, 타입, 공격 타입, 피해 타입, 방어력, 능력치, 효과를 표시

강화 규칙은 다음과 같다.

- 최대 레벨 13
- 다음 레벨 비용은 임시로 골드 = 목표 레벨 × 3
- 필요한 카드 수 = 목표 레벨 × 3
- 1, 2, 4, 5, 7, 8, 10, 11, 12레벨은 HP +1
- 3, 6, 9, 13레벨은 ATK +1
- 일부 건물과 주문은 별도 강화 규칙을 사용한다.
- 파이어볼과 이후 일부 피해 마법은 레벨에 따라 피해를 증가시킬 수 있다.
- 개방 지부와 로봇 공장은 레벨마다 HP +1이다.

### 3.27 상대 손패, 덱, 카드 공개

상대 정보는 카드 정체를 숨기면서 개수는 보여주는 방향으로 만들었다.

- 상대 손패는 카드 뒷면 이미지로 표시한다.
- 상대 손패 수만큼 카드 뒷면을 펼친다.
- 자신의 덱은 오른쪽 하단에 카드 뒷면 더미로 표시한다.
- 자신의 덱을 누르면 남은 카드 수를 안내한다.
- 상대 덱은 왼쪽 상단에 표시한다.
- 상대가 카드를 사용하면 중앙에 실제 카드 이미지를 공개한다.
- 평소 3초 표시하고 대기열이 있으면 2초로 줄이는 적응형 대기열을 사용한다.
- 페이드 인 0.15초, 유지, 페이드 아웃 0.15초다.
- 배경을 어둡게 하지 않고 입력을 막지 않는다.
- 실제 강화 ATK/HP를 표시한다.
- 재접속 시 과거 카드 공개 연출은 다시 재생하지 않는다.

### 3.29 보상형 광고

GameStart에 광고 시청 후 티켓 +1 버튼을 추가했다.

보상은 클라이언트가 직접 지급하지 않는다.

1. Unity가 광고 시도 토큰을 서버에서 받는다.
2. Unity LevelPlay가 보상형 광고를 표시한다.
3. LevelPlay S2S callback이 After333 서버로 전송된다.
4. 서버가 서명, 이벤트 ID, 사용자, placement, 제한을 검증한다.
5. PostgreSQL transaction으로 티켓을 1장 지급한다.

현재 설계에는 다음 제한이 있다.

- 동일 이벤트 중복 지급 금지
- 일일 지급 제한
- cooldown
- LevelPlay private key는 서버에만 저장

실제 테스트 중 invalid_callback_signature가 발생했고, LevelPlay S2S private key와 서버 환경변수를 정확히 맞춰야 하는 상태였다.

## 4. 오전 9시 39분 직전 카드 제작 단계

### 4.1 카드 제작 방식

사용자는 앞으로 카드 데이터를 직접 작성하는 능력을 기르고 싶다고 요청했다.

그에 따라 카드 제작 절차를 다음처럼 문서화했다.

1. 카드 규칙을 먼저 확정
2. 고유 cardId 결정
3. cards.json에 데이터 추가
4. 새 규칙이면 전용 Rules 또는 Service 작성
5. 서버와 Unity가 공유하는 도메인 계층에 연결
6. CardDatabaseValidator에 불변식 추가
7. 강화 규칙 연결
8. 서버 StateView와 BattleEvents 연결
9. Unity 연출과 툴팁 연결
10. EditMode 테스트와 서버 build 실행
11. 이미지가 준비되면 includeInDraft와 includeInRewards를 true로 전환

이미지가 준비되지 않은 개발 카드들은 다음처럼 둔다.

- includeInDraft: false
- includeInRewards: false

## 6. 현재 확인된 중요한 미완료·주의 사항

### 6.1 대화 원문

이 문서는 원문 메시지의 완전한 사본이 아니다.
정확한 표현이나 개별 메시지 시각이 필요한 경우 채팅 서비스의 원본 기록 복구가 필요하다.

### 6.2 문서 간 오래된 표현

일부 문서에는 과거 상태가 남아 있다.

예를 들어 online_pvp_prototype.md 일부에는 게스트 계정이 유효하다고 적혀 있지만, 현재 계정 설계와 migration 0010은 게스트 계정을 비활성화한다.
현재 제품 방향은 게임 ID 또는 Google 계정 로그인이 필수인 쪽이다.

### 6.3 아직 남은 외부 서비스 작업

- Kakao 로그인
- Naver 로그인
- 실제 VPS 배포
- 운영 PostgreSQL 또는 managed DB
- 자동 백업과 복구 훈련
- 실제 부하 테스트
- LevelPlay S2S 서명 설정 최종 확인
- Google OAuth 공개 상태와 정식 출시 전 검토

### 6.4 아직 남은 카드 작업

- 원자력 발전소 구현

- includeInDraft와 includeInRewards 최종 전환
- 카드별 밸런스 검증

### 6.5 동시 마스터 사망 규칙

양쪽 마스터가 같은 효과로 동시에 0 이하가 되는 경우 최종 HP가 더 낮은 쪽이 패배한다는 규칙이 제안됐다.

예시:

- A 마스터 20, B 마스터 30
- 양쪽이 40 피해
- A 최종 HP -20, B 최종 HP -10
- A 패배, B 승리

최종 HP까지 같은 완전 동률일 때의 처리 규칙은 별도 확정이 필요하다.
