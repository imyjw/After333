# 한 계정의 단일 로그인

2026-10-21 소스 변경. **운영 서버 배포, 운영 DB의 0025 적용, 사용자 클라이언트 빌드·설치는 아직 수행하지 않았다.** 마지막으로 사용자가 확인한 Lightsail 운영 DB는 migration 24개/latest `0024_elf_elder_card_id`다. 이 문서는 새 소스의 동작 계약이며 운영 적용 완료를 뜻하지 않는다.

## 플레이어에게 보이는 동작

한 계정에서는 마지막으로 성공한 독립 로그인을 사용한다. 다른 기기에서 Game ID 또는 Google 로그인을 완료하면 먼저 로그인했던 기기의 자격 증명과 전투 연결이 종료되고 다음 안내를 표시한다.

> 다른 기기에서 로그인하여 연결이 종료되었습니다.

비밀번호 오류나 실패한 Google 인증은 기존 로그인을 종료하지 않는다. 같은 기기에서 저장된 토큰으로 자동 로그인하거나 정상적으로 토큰을 갱신하는 것은 새 독립 로그인이 아니므로 기존 전투 연결을 유지한다. 로그아웃된 기기는 Game ID 또는 Google 버튼으로 직접 다시 로그인할 수 있다. 이때 다시 로그인한 기기가 최신 로그인이 된다.

기존 기기는 저장된 session/refresh token을 지우고 Google 자동 로그인을 억제한다. 자동으로 재로그인하여 다른 기기를 다시 밀어내지 않는다. 계정, 보유 카드, 강화, 골드, 티켓, 런과 서버의 확정 결과는 삭제하지 않는다. 전송 결과가 불확실한 구매·강화 요청 ID와 미표시 보상·광고 복구 기록도 보존하고 같은 계정으로 로그인한 뒤 서버 기록을 확인한다.

## 감지와 API 계약

- 교체된 session token 또는 refresh token은 HTTP `401`과 오류 코드 `session_replaced`, 위 안내 문구를 반환한다. 일반 만료·잘못된 토큰과 구분한다.
- `GET /auth/session-status`는 Bearer token의 유효성만 확인한다. 성공하면 `Status: Ok`를 반환하며 지갑·보유 카드 전체를 읽지 않는다. 인증 시도 한도 대신 계정 API 한도를 사용한다.
- Unity의 `AccountSessionGuard`는 로그인된 앱이 화면 앞에 있는 동안 5초 간격으로 이 API를 조회한다. 포커스 복귀·앱 재개 시에도 확인한다. 중복 조회는 만들지 않으며, 로컬 튜토리얼 중에는 조회와 강제 화면 이동을 하지 않는다. 통신 실패만으로 중복 로그인이라고 판단하지 않는다.
- 전투 중에는 서버가 기존 WebSocket에 `session_replaced` 오류를 보내고 close code `1008`, close reason `session_replaced`로 종료한다. 클라이언트는 항복이나 로컬 승패를 생성하지 않고 자동 전투 재접속을 중단한다.
- 같은 로그인에서 토큰을 갱신하면 WebSocket은 유지된다. 이후 다른 기기 로그인이 발생할 때 기존 소켓에 저장된 access token과 현재 토큰이 다르면, 소켓 중단 뒤 전체 로그아웃 안내는 다음 5초 주기의 HTTP 검사에서 처리될 수 있다. 실제 감지 시간에는 통신 왕복·진행 중 요청 시간이 더해질 수 있으므로 5초 이내를 보장하는 타이머는 아니다.
- 응답은 실제 서버 주소와 요청 당시 자격 증명에 연결한다. 서버를 바꾸거나 새 로그인이 완료된 후 도착한 오래된 응답이 최신 로그인을 지우거나 예전 계정 상태를 되살리지 않도록 폐기한다.

## 진행 중인 전투

기존 로그인 종료는 일반 연결 종료 경로를 사용한다. 실행 중인 서버는 기존 계정의 좌석, 런·덱·강화·손패·전장을 70초 재접속 유예 동안 유지한다. 최신 기기는 로그인 후 시작 화면 또는 덱 화면의 재접속 버튼으로 원래 전투에 복귀한다. 예전 소켓의 연결 ID를 새 기기가 갖고 있을 필요는 없다.

로그인 교체 자체로 패배·보상·런 결과를 확정하지 않는다. 기존 턴 시간과 AI 진행은 계속되며, 기존 규칙에 따른 재접속 유예 만료나 실제 전투 종료는 그대로 적용한다. 서버 장애·점검으로 미완료 전투를 취소하는 정책도 유지한다. 서버 재시작 뒤 진행 중 전투를 복원하는 기능은 추가하지 않는다.

## 로그인 family와 DB 변경

마이그레이션 `0025_single_login_family.sql`은 다음 필드를 추가한다.

| 대상 | 추가 내용 |
| --- | --- |
| `accounts` | 현재 허용된 `active_login_family_id` |
| `auth_sessions` | 소켓과 토큰을 연결하는 `login_family_id`, 교체 시각 `superseded_at` |
| 인덱스 | 미폐기 session의 계정·family 조회 인덱스 |

refresh 회전은 동일 family를 이어간다. 독립 로그인은 계정 행을 잠그고 이전 access/refresh token을 폐기한 뒤 새 family를 활성화하는 한 트랜잭션으로 처리한다. 병렬 로그인 중 마지막으로 확정된 family 하나만 유효하다. refresh·로그아웃도 같은 계정 잠금 순서를 사용하며, 오래된 기기의 로그아웃이 새 family를 폐기하지 않는다. 전투 명령은 family 검증과 짧은 실제 상태 변경을 계정 잠금 안에서 처리하여 새 로그인 확정 후 예전 기기의 명령을 받아들이지 않는다.

기존 데이터에서는 refresh 이력에 연결된 family를 채운다. 정상적으로 연결되고 유효한 refresh가 남은 family 중 가장 최근에 독립 생성된 family 하나를 유지한다. 과거 family가 나중에 refresh되었다는 이유로 최신 독립 로그인을 이기지 않는다. access token만 만료되었고 refresh가 유효한 경우에는 갱신 경로를 유지한다. family 연결이 없거나 모호한 기존 access session과 선택되지 않은 family는 폐기하므로 해당 기기는 직접 다시 로그인해야 할 수 있다. 계정 소유 데이터·경제 데이터·런은 초기화하지 않는다.

## 적용과 복구

새 서버 실행본, 0025 마이그레이션, 새 클라이언트를 함께 준비하고 운영 백업 및 현재 실행본을 보관한 뒤 적용한다. 이 작업에서 운영에는 적용하지 않았다. 일반 코드 교체용 절차의 migration 일치 검사를 무시해서는 안 된다.

**참여하는 모든 기기의 클라이언트를 업데이트해야 한다.** 예전 앱은 `session_replaced`를 인식하지 못하고 실패한 세션 복구 뒤 Google 자동 로그인을 다시 시도할 수 있다. 현재 `PROJECT333_REQUIRED_CLIENT_VERSION` 검사는 전투 JoinMatch에 적용되며 독립 로그인 API에는 적용되지 않으므로, 버전 설정만 높여 예전 앱의 Google 재로그인이 차단된다고 간주하지 않는다.

0025는 이전 세션을 폐기하는 데이터 변경도 포함한다. 단순히 열을 삭제하거나 마이그레이션 이력만 되돌리면 이전 토큰 상태가 복구되지 않는다. 복구 시에는 쓰기를 중지하고 호환되는 실행본과 백업 시점의 DB를 함께 검토해야 하며, 백업 이후 확정된 경제·런 변경을 잃지 않도록 별도 복구 판단이 필요하다. 새 서버에 필요한 필드를 제거한 DB로 그대로 실행하지 않는다.

## 검증 범위

2026-10-21 별도 임시 PostgreSQL·루프백 서버에서 집중 검사 **14개 그룹이 통과**했다. 실제 마이그레이션의 기존 family 변환, 병렬 로그인·refresh/로그인 경쟁, 이전 토큰/로그아웃 격리, 교체 알림, 상태 API 한도를 검사했다. 실제 WebSocket으로 두 계정의 PvP와 골드 던전 PvE에서 기존 연결 종료, 최신 기기의 원래 좌석 재접속, 상대 계정 및 손패·체력·자원·타이머 보존을 확인했다.

별도 일반 서버 회귀 검사 130개와 프로세스 재시작·DB 미설정 검사 5개도 통과했다. 서버 최종 빌드는 오류 0개이며 기존 경고 101개가 남아 있다. 게임 밸런스는 변경하지 않았다. 기존 경제 검사에 남은 강화 Lv.2 비용 기대값 5/5는 현재 확정 비용 6/6에 맞추었고, 병렬 로그인·폐기 시각에는 트랜잭션 시작 시각인 `now()` 대신 `clock_timestamp()`를 사용하여 생성 이후 시각 제약을 유지한다.

격리 Unity 6000.3.12f1에서 EditMode 53/53, PlayMode 1/1이 통과했다. 이전 자격 증명 응답 폐기, 서버 주소 변경, 실제 HTTP 401 오류 인식, 자동 Google 재로그인 억제, 전투 재접속 중단 및 튜토리얼 격리를 검사했다. PlayMode에서는 실제 설치된 영속 세션 가드와 GameStart 컨트롤러의 로그인 선택창, 정확한 한국어 안내, 확인 후 입력 차단 해제를 확인했다. 기존 인증 로딩 상태도 교체 시 명시적으로 해제한다. 검증용 합성 계정·임시 씬·메모리 자격 증명 저장소를 사용했으며 실제 Google 제공자 인증은 이 검사에서 호출하지 않았다. 운영 서버 및 운영 DB를 사용한 시험, 사용자 기기의 새 앱 빌드·설치 검증은 수행하지 않았다.

## 2026-10-22 강제 로그아웃 후 수동 Google 로그인 복구

사용자는 휴대폰 PvP 중 다른 기기 로그인으로 기존 기기가 로그아웃되는 동작을 확인했으나, 돌아온 로그인 창의 Google 버튼이 계속 준비 중인 문제를 보고했다. 시작 씬의 초기 공개 상태 조회가 강제 로그아웃의 계정 복구 취소에 함께 취소되어 Google 설정 캐시가 비는 경합을 재현했다.

캐시가 없으면 계정 복구와 분리한 `/server/status` 조회로 Google 사용 가능 여부를 다시 확인한다. 실제 플랫폼·Client ID·서버 설정 조건을 만족하면 `Google로 로그인`을 활성화하며, 자동 Google 로그인 억제와 기존 세션 폐기는 유지한다. 토큰 갱신·자동 재로그인·전투 재접속은 하지 않는다. 중복 요청, 화면 종료, 서버 주소 변경과 튜토리얼 격리도 처리한다.

격리 Unity에서 변경 전1개 재현 실패, 수정 후 EditMode76개 및 PlayMode1개 통과. 이 수정은 클라이언트 빌드·설치로 반영한다. 서버 재배포나 추가 DB 마이그레이션은 필요하지 않으며, 이번 조사에서 운영 DB 버전을 새로 확인한 것은 아니다. 실제 휴대폰과 Google 인증 제공자 호출은 별도 재확인 대상이다.
