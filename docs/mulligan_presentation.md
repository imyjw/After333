# 멀리건 화면과 카드 등장·교체 연출

2026-10-02 사용자 요청으로 전투 시작 멀리건 화면을 개선했다. 부분 교체 규칙·서버 확정·33초 제한은 [전투 규칙](battle_rules.md)의 Mulligan 항목을 따른다.

## 화면

- 전장을 어둡게 덮고, 위쪽에 픽셀 테두리의 `시작 핸드 카드` 제목과 `교환할 카드 선택` 안내를 표시한다. 선공·후공은 오른쪽 위에 별도로 표시한다. 기존 남은 시간 안내창을 위한 상단 공간을 확보한다.
- 중앙의 시작 카드 3장은 실제 카드 이미지와 기존 공격력·HP 표시를 사용한다. 유지할 카드에는 부드럽게 밝기가 변하는 초록색 오오라를 표시한다.
- 교체할 카드를 클릭하면 초록색 오오라가 사라지고 명암·입체감과 다듬은 끝 모양을 갖춘 붉은 픽셀 X 이미지와 카드 아래 `교체` 문구가 나타난다. 다시 클릭하면 유지 상태로 돌아간다.
- 카드 아래 `확인` 버튼으로 0~3장 교체를 한 번 확정한다. 전송 중에는 입력을 잠그고, 실패하면 다시 선택할 수 있다. 상대를 기다리는 중과 최종 결과에서는 선택 표시를 제거한다.
- 안내 글꼴은 기존 NeoDunggeunmo Pro를 재사용한다. 카드 능력치 글꼴과 원본 카드 아트는 보존한다. Safe Area와 CanvasScaler를 기준으로 화면 비율에 맞춰 배치한다.

## 덱에서 등장하는 카드

- 첫 미확정 멀리건 화면에 진입하면 오른쪽 아래 내 덱의 맨 위 카드 위치에서 시작 카드가 한 장씩 날아온다. 출발점은 `PlayerDeckPresenter.DrawSourceRect`의 실제 화면 좌표다.
- 비행 중 카드가 커지며 중앙의 제시 위치로 이동하고, 카드 뒷면에서 실제 카드 앞면으로 뒤집힌다. 카드당 기본 0.48초, 카드 사이 기본 0.13초 간격으로 총 약 0.74초다.
- 등장 중에는 선택·확정을 잠그고, 모두 도착하면 선택할 수 있다. `Time.unscaledDeltaTime`으로 재생하므로 게임 시간 배율과 무관하다. 서버 멀리건 제한 시간은 계속 흐른다.
- 반복 상태 갱신으로 같은 카드를 다시 뽑지 않는다. 확정된 멀리건을 재접속으로 복원할 때는 등장·교체 연출을 건너뛴다. 화면 크기 변경·시간 초과·화면 종료가 발생하면 비행용 이미지를 정리하고 실제 카드 상태를 표시한다.
- 출발 덱 UI가 없는 테스트/간소화 화면에서는 Safe Area의 오른쪽 아래를 사용한다.
- 이는 표시용 이미지의 이동이다. 덱 드로우, 손패, 자원, 서버 상태 또는 전투 이벤트를 추가로 변경하지 않는다.

## 선택한 카드 교체

- `확인`을 누르면 선택한 자리의 카드·X·능력치가 즉시 사라지고, 유지할 카드는 그대로 남는다. 서버 응답 전까지 그 자리를 비워 둔다. 즉시 제출에 실패하면 사라진 카드와 선택 표시를 복원하여 다시 선택할 수 있다.
- 서버가 확정한 실제 교체 카드를 받으면, 선택한 자리로만 오른쪽 아래 내 덱에서 새 카드가 날아온다. 시작 카드와 같은 이동·확대·뒤집기 연출과 0.48초/0.13초 간격을 사용한다. 같은 이름의 카드가 여러 장 있어도 선택한 개별 자리로 처리한다.
- 교체가 없는 확정은 비행 없이 유지한다. 상대가 아직 선택 중이면 새 카드 도착 후 대기 문구를 표시한다. 전투 단계로 바뀌어도 교체 비행을 끝까지 재생하고, 모두 도착한 뒤 최종 결과 표시 3초를 시작한다.
- 교체 비행 중에는 진행 안내 문구를 표시하지 않는다. 교체 카드를 표시하는 동안 다시 선택하거나 확정할 수 없다. 표시 전용 이미지만 이동하며 서버 손패·덱·자원·이벤트를 변경하지 않는다.

## 구현과 조정

- `Assets/Project333/Runtime/Presentation/Battle/BattleMulliganOverlayPresenter.Design.cs`: 화면 스타일, 배치, 오오라, X 이미지, 교체 문구와 공통 카드 비행 코루틴. `_openingCardFlightSeconds`, `_openingCardStaggerSeconds`, `_dealOpeningHand`로 등장 속도/사용 여부를 조정한다.
- 기존 `BattleMulliganOverlayPresenter.cs`: 부분 교체 선택, 확정/대기/결과 상태. 교체 비행 완료 후 결과를 3초 동안 표시하고 닫힌다.
- `BattleScreenPresenter.cs`가 내 덱 출발 위치와 뒷면 이미지를 주입한다. 기존 씬의 직렬화된 UI 참조를 재사용하며, `Project333BattleMulliganOverlayBuilder`도 기존 오버레이를 파괴하지 않고 같은 스타일을 적용한다.

- 새 X 자산: `Assets/Project333/Resources/Project333/UI/MulliganReplaceMark.png` (1024×1536, 실제 투명 알파). 내장 이미지 생성 도구로 제작했으며 원본과 최종 프롬프트는 `Tools/Art/Source/MulliganReplaceMark/`에 보존한다. UI Image를 흰색 tint·종횡비 유지·raycast 비활성으로 표시한다. Sprite Single·Point·FullRect·mipmap 없음으로 네이티브 Unity에서 임포트한다.

## 교체 연출과 새 X 검증 (2026-10-02)

- 최종 수정 소스로 격리 Unity 6000.3.12f1 관련 검사 135/135 통과, 컴파일 오류·실패·스킵 0. 0~3장 교체·중복 카드의 개별 자리·동기/비동기 응답·제출 실패 복원·반복 상태 갱신·비행 중 Main 전환·도착 후 3초·시간 배율 0·레이아웃/비활성/재접속 정리를 확인했다. 교체 비행 중 상태 문구가 비어 있는 것도 검사했다.
- 실제 Battle_VSlice 씬에서 1920×1080, 2340×1080의 총 12 장을 네이티브 GPU로 캡처하여 새 X·선택 자리 숨김·비행·뒤집기·도착·최종 표시를 확인했다.
- 새 PNG는 기존 GUID를 유지한 네이티브 Sprite 임포트 설정을 적용했다. 2665개 검사 입력과 실제 수정 소스를 대조했고, 7797개 기존 자산·설정과 원본 Editor를 보존했다. 새 이미지의 기본 Texture→Sprite 메타데이터 변경만 승인된 임포트 차이로 기록했다.
- 초기 검증 사본의 이전 Library 캐시로 생긴 씬 스크립트 연결 오류를 사본 캐시 재임포트로 해결했다. 테스트의 Sprite 관리 객체 참조 동일성 비교는 재임포트 후에도 유효한 자산 경로에서 얻은 영구 GUID 비교로 수정했다. 실패 실행은 attempts에 보존했다.

## 시작 카드 연출 검증 (앞선 작업)

- 격리된 Unity 6000.3.12f1에서 관련 검사 122/122 통과, 컴파일 오류·실패·스킵 0. 등장 중 선택/확정 잠금, 시간 배율 0, 중복 카드의 개별 선택, 강제 레이아웃 변경 시 정리, 시간 초과, 확정 대기, 재접속, 최종 3초 표시를 확인했다.
- 실제 Battle_VSlice 씬을 GPU로 렌더링한 28장 캡처를 검토했다. 1920×1080, 1280×720, 1600×1200, 2340×1080에서 덱 출발·비행·도착·교체·대기·최종 결과를 확인했고 기존 시간 안내창과 제목의 겹침을 검사했다.
- 원본 씬·자산·설정 7797개와 기존 실행 중인 Editor를 보존했다. 당시 소스와 검증 사본의 기록된 입력 2659개가 일치했다. 새 스크립트와 검사 파일의 .meta는 네이티브 Unity가 생성한 파일을 사용한다.
- 앞선 실패 실행은 attempts에 보존했다. Unity 컴포넌트의 fake-null 생성 오류, 숨겨진 예비 슬롯을 포함한 카드 배치, 화면 갱신 시 표시 상태를 수정했다. 테스트의 실제 씬 슬롯 수와 캡처 시간 가정도 실제 실행 방식에 맞췄다.
- 증거: TempBuild/MulliganRedesign_20261002/unity-results.xml, unity-summary.json, final-preservation-proof.json, captures/. 클라이언트 빌드·기기 설치·실서버 연결/배포는 이 작업에서 실행하지 않았다.
