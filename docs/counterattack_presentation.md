# 반격 후 Idle 복귀

2026-10-26 수정. 전투 판정·카드 수치·사용자 애니메이션 자산은 바꾸지 않는다.

## 증상과 원인

피해가 막힌 오크 족장이 반격 후 Attack의 마지막 자세에 남고, 이동하면 정상화되는 보고를 조사했다. 첨부 화면의 `35→35, 방어됨` 기록과 일치하는 조건을 실제 오크 족장·뱀파이어 컨트롤러로 재현했다.

- 방어로 피해가0이면 일반 피해 팝업 이벤트가 생략되고, 무적으로 막힌 경우에는 InvinciblePrevented만 기록된다. 온라인 연출 요청의 DefenderImpacts에는 실제 피해·제거가 있는 대상이 들어간다. 로컬 요청도 체력 변화나 사망이 없으면 impact를 생략한다.
- 공통 공격 연출은 반격 여부를 보고 방어자에게 Attack을 재생하지만, 마무리 시에는 DefenderImpacts의 피해 대상만 Idle로 되돌렸다. 그래서 피해 없이 반격한 생존자는 복귀 대상에서 빠졌다. 공격자가 반격으로 죽으면 이후 공격자 사망 대기 후 바로 종료되는 경로에서도 그대로 남았다.
- 현재 오크 족장의 Attack은 Loop Time=0이며 자동 Idle 전환이 없다. 따라서 누락된 복귀 요청은 마지막 모션을 계속 보이게 한다. 이동하면 새 타일에서 비주얼을 바인딩하고 Idle을 시작해 정상화될 수 있다. 사용자 클립/컨트롤러를 고칠 문제로 처리하지 않는다.

## 수정

`Assets/Project333/Runtime/Presentation/Battle/BattleBootstrapper.cs`의 `PlayAttackAnimationSequence`에서, 피해/사망 처리로 이미 마무리한 반격자를 구분한다. 아직 처리하지 않은 반격 유닛은 활성 상태와 같은 RuntimeId를 확인해 Idle로 돌린다. 이 처리는 공격자가 반격으로 사망한 경우의 조기 종료보다 먼저 실행한다. 사망한 반격 유닛의 Death 연출은 Idle로 덮어쓰지 않는다.

## 검증과 반영

- 수정 전 실제 Play 재현3개 중 무피해/무적 반격2개가 Idle 복귀 실패, 피해·사망 대조 검사는 통과했다. 수정 후3개 모두 통과했으며 Native Animator 상태와 Image.sprite가 실제 Idle/Death 클립의 프레임인지 함께 확인했다.
- 기존 반격 이벤트·다중 반격·사용자 컨트롤러 재생·이동교환까지 **고유 검사41개 최종 통과**. 전체 실행36/41에서 자산 누락으로 준비에 실패한 이동교환5개만, 검증 사본에 마스터 카드·현재 엘프 장로 원본 자산을 보완한 뒤5/5 통과했다. 통과한36개는 다시 실행하지 않았다.
- SDK 없는 격리 Unity6000.3.12f1에서 `-nographics`로 검사했다. 실제 Animator/스프라이트 검사는 수행했으나 GPU 화면 캡처·실제 PVP 세션·폰 확인은 수행하지 않았다. native LevelPlay 제외는 검증 사본에만 적용한다.
- Unity에서는 컴파일 완료 후 Play를 다시 시작해 확인한다. 배포된 앱은 사용자가 클라이언트를 다시 빌드·설치한다. 서버 재배포·DB 마이그레이션은 필요 없다.

상세 실패/수정 이력과 증거 위치는 [handoff](codex_handoff.md)의 2026-10-26 반격 Idle 항목을 따른다.
