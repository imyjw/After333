## 상품과 추첨 규칙

- `Shop_VSlice` 상점에서 카드팩 1개를 **계정 Resource Gold 33**에 구매한다. 전투에서 사용하는 골드와 별개다.
- 구매 1건마다 랜덤 카드 **10장**을 서버가 추첨하고 보유카드 컬렉션에 즉시 더한다. 별도의 미개봉 팩 재고나 나중에 받기 위한 보상 수령 단계는 없다.
- 10장은 각각 독립적으로 추첨한다. 같은 카드가 여러 장 나올 수 있으며, 결과 화면에서도 10개 슬롯을 유지한다.
- 각 장은 아래 확률로 희귀도를 먼저 추첨하고, 해당 희귀도의 보상 가능 카드 중에서 같은 확률로 1장을 선택한다. 10장에 특정 희귀도가 반드시 나온다는 보장은 없다.

| 희귀도 | 1장당 등장 확률 |
| --- | --- |
| 커먼 | 40% |
| 언커먼 | 30% |
| 레어 | 18% |
| 유니크 | 9% |
| 레전더리 | 3% |

카드 후보는 런 종료 랜덤 카드 보상과 같은 `RewardCardEligibility` 필터를 사용한다. 마스터는 제외하고, `includeInRewards` 및 강화 가능 정책과 사용자 확정 `TrapReturn` 예외를 적용한다. 현재 보상 대상 집계와 플래그는 [메타 규칙](meta_rules.md#rewards)과 [카드 목록](card_catalog.md)을 따른다. 드래프트에 등장한다는 이유만으로 카드팩 대상이 되지는 않는다.

카드팩은 위 고정 확률을 보장하기 위해 다섯 희귀도 모두에 보상 가능 카드가 있어야 한다. 어느 희귀도 후보가 비었거나 후보 ID가 중복되는 등 풀 구성이 유효하지 않으면 `card_pack_pool_unavailable`로 차감 전에 구매를 거절한다. 기존 런 보상의 빈 희귀도 정규화 규칙을 카드팩에 적용하지 않는다.

## 서버 구매 계약

인증된 bearer 계정에서 다음 API를 사용한다. 카드팩 구매 POST와 영수증 GET은 모두 기존 계정 API IP 제한 범주를 사용한다(기본 60초당 120회).

| API | 목적 |
| --- | --- |
| `POST /shop/purchase-card-pack` | `{ "RequestId": "비어 있지 않은 D-format UUID" }`로 카드팩 1개 구매 |
| `GET /shop/card-pack-purchases/{requestId}` | 해당 계정의 이미 확정된 원래 구매 영수증 조회. 차감·지급·추첨 없음 |
| `POST /account/operations/resolve` | 통신 중단으로 미확정인 동일 RequestId를 완료 또는 영구 취소 상태로 확정 |

구매 응답에는 `RequestId`, `Replayed`, `ResourceGoldCost`, `Account`, `Wallet`, 원래 추첨 순서의 `CardIds` 10개가 들어간다. 중복 카드 ID도 목록에 그대로 유지한다. 결과 재조회는 원래 비용·10장을 보존하고 현재 계정 지갑을 반환한다. 클라이언트가 보낸 비용·카드 목록·희귀도·보유량은 결제 근거로 사용하지 않는다.

`CardPackService`는 기존 구매·강화·작업 확정과 같은 계정 지갑 행 잠금을 사용하고, 하나의 READ COMMITTED DB 트랜잭션에서 다음 내용을 확정한다.

1. 계정·RequestId의 원래 성공 영수증 또는 취소 기록 확인
2. 33 Resource Gold 차감과 추첨한 10장 컬렉션 증가
3. 차감·카드 증가 거래 내역과 원래 순서의 성공 영수증 저장
4. 전체 커밋

커밋 전 실패는 전체 롤백이며, 커밋 후 응답 유실은 이미 지급된 동일 영수증으로 복구한다. 같은 계정·RequestId를 재사용해도 다시 차감하거나 추첨하지 않는다. 다른 작업이나 다른 입력에 같은 ID를 재사용하면 충돌로 거절한다. 완료 영수증과 취소 기록은 계정 수명 동안 보존한다. 현재 카드 풀에서 제외되었더라도 이미 커밋된 영수증의 원래 10장은 재추첨하지 않는다.

작업 확정 API는 원래 성공이 있으면 `completed`, 없으면 영구 취소 기록을 만들어 `cancelled`를 반환한다. 이후 지연 도착한 취소된 구매는 차감·지급하지 않는다. 조회 응답이 없다는 이유로 새 구매를 자동 재전송하거나 취소됐다고 단정하지 않는다. 자세한 공통 규칙은 [구매·강화 복구](account_operation_retries.md)를 따른다.

## 클라이언트 복구와 표시 대기

구매 의도 RequestId를 HTTP 전송 전에 영속화하며 서버·인증 계정에 맞춰 구분한다. 미확정 구매가 있으면 다른 구매·강화 입력을 막고, 연결이 돌아오면 기존 계정 작업 복구 경로로 자동 확정·`/me` 새로고침을 수행한다. 새 결제를 자동으로 보내지 않고, 별도의 이전 구매 확인 버튼을 추가하지 않는다.

결제가 확인된 카드팩은 **이미 보유카드에 지급되어 있다**. 개봉은 원래 10장을 보여주는 화면 연출이다. 계정·서버·RequestId의 로컬 표시 대기를 결과 확인 전까지 유지하고, 상점을 다시 열면 원래 구매 영수증을 조회해 같은 10장의 닫힌 카드팩을 표시한다. 클라이언트는 개봉하거나 복원할 때 카드 수를 다시 더하지 않는다. 결과 화면을 닫아 확인한 뒤 해당 표시 대기만 지운다.

계정·세션·서버가 달라졌거나 화면 소유자가 비활성화되면 늦은 응답을 이전 화면에 적용하지 않는다. 복구 실패 시 미확정 의도와 미확인 표시 정보는 다음 시도를 위해 남긴다. 알 수 없는 카드 ID나 누락된 그림은 ID·이름 대체 표시로 유지하며 다른 카드로 바꾸거나 재추첨하지 않는다.

| 중단·오류 상황 | 처리 |
| --- | --- |
| 전송·커밋 전에 강제 종료 | 작업 확정에서 완료 여부를 확인한다. 원래 완료가 없으면 영구 취소하며 지연 요청도 차단한다. |
| 커밋 후 응답을 받기 전에 종료 | 원래 RequestId의 완료 영수증·현재 컬렉션을 복구한다. 추가 차감·재지급 없음. |
| 닫힌 카드팩·개봉 애니메이션·결과 화면에서 종료 | 지급은 유지한다. 같은 계정으로 상점에 재진입하면 동일 10장을 다시 개봉·확인한다. |
| 빠른 구매·개봉 연타 | 미확정 구매 및 표시 중 구매 입력을 막고, 개봉은 한 번만 시작한다. |
| 33골드 부족 | 지급·차감 없이 거절한다. |
| 서버 장애·잘못된 영수증 | 결과를 만들어내지 않는다. 원래 작업/표시 정보를 유지해 재시도한다. |
| 계정 전환 | 다른 계정에 영수증·카드 목록·지갑을 적용하지 않는다. |

로컬 표시 대기는 기기 간 읽음 동기화나 서버의 미개봉 팩 재고가 아니다. 앱 데이터 삭제·새 기기로의 변경은 로컬 표시 의도와 RequestId를 잃을 수 있지만, 이미 커밋된 골드 차감·카드 지급·영수증은 서버에 남는다. 전체 구매 내역 조회 화면이나 다른 기기에서 자동 재개하는 서버 표시 대기 기능은 이번 범위에 포함하지 않았다.

## 개봉 연출과 입력

구매 확인 후 상점 화면을 어둡게 하고 중앙에 닫힌 포일 카드팩을 표시한다. 중앙 카드팩을 클릭하면 상단이 분리되며 뜯기고, 하얗게 빛나는 카드 10장이 빠르게 위로 튀어나온다. 이어서 원래 추첨 순서의 실제 카드 10장을 화면의 **5열 × 2행**으로 표시한다.

- 레어: 파란색 테두리 오오라
- 유니크: 붉은색 테두리 오오라
- 레전더리: 더 많은 빛 입자를 동반한 화려한 노란색 테두리 오오라
- 커먼·언커먼: 일반 테두리

제목·카드 이름·희귀도·안내 문구는 기존 `NoticeTheme`의 NeoDunggeunmo Pro 글꼴을 사용한다. 카드 그림은 원래 종횡비를 유지하며, 복수 장의 같은 카드를 하나의 수량 행으로 합치지 않는다. 해상도와 모바일 가로 화면의 안전 영역에 맞춰 같은 5×2 배열로 배치한다.

개봉 진행 중 배경 클릭과 연타로 연출을 건너뛰거나 상점 입력을 전달하지 않는다. 결과 카드가 모두 나타난 후 짧은 입력 지연이 지나면 화면의 아무 곳이나 클릭해 상점으로 돌아간다. 화면을 닫는 동작은 결과 표시 확인만 처리한다. 애니메이션은 unscaled time을 사용하며 비활성화·종료 시 재생만 중단한다. 추가 효과음은 요청되지 않아 별도 카드팩 음원을 추가하지 않는다.

연출 구현은 `Assets/Project333/Runtime/Presentation/Shop/ShopCardPackRevealView.cs`, 원본 그림은 `Assets/Project333/Resources/Project333/UI/Shop/CardPackStates.png`이다. Resources 경로는 `Project333/UI/Shop/CardPackStates`, 네이티브 스프라이트 이름은 `CardPackClosed`, `CardPackOpen`, `CardPackTornTop`이며 3개 프레임은 같은 크기의 투명 셀을 사용한다. 그림 제작 프롬프트·네이티브 임포트 기록과 검증 자료는 작업 증거에 남긴다.
